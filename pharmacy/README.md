# 약국 입고 스캐너 (Pharmacy Barcode Scanner) v0.1

스마트폰 카메라로 의약품 바코드를 스캔하고 **입고 기록**을 남기는 모바일 웹앱입니다.
서버·회원가입·외부 전송 없이, 데이터는 **그 스마트폰 브라우저의 localStorage에만** 저장됩니다.

> 입고 기록용 보조 도구입니다. IT3000과 연동하지 않으며, 재고 수량·조제 가능 여부를 판단하지 않습니다.
> 환자 개인정보·처방전·조제 이력은 입력하지 마세요.

## 1. 실행 · 스마트폰 접속

스마트폰 브라우저는 **HTTPS 주소에서만 카메라를 허용**합니다. 아래 중 하나로 접속하세요.

### A. GitHub Pages (권장 — iPhone·Android 공통, 정식 HTTPS, PC 불필요)

이 저장소는 이미 GitHub Pages가 `main` 브랜치 루트에서 배포되고 있습니다(블로그: `https://sunnnown.github.io/my-blog/`).
`pharmacy/` 폴더가 `main`에 병합되면 1~2분 뒤 아래 주소가 열립니다. 블로그 파일은 바뀌지 않습니다.

- 앱: `https://sunnnown.github.io/my-blog/pharmacy/`
- 기기 점검·테스트 바코드: `https://sunnnown.github.io/my-blog/pharmacy/test.html`

페이지 파일(코드)만 공개되며, 입력한 입고 데이터는 각 기기 브라우저에만 남고 GitHub로 전송되지 않습니다.

### B. Mac에서 로컬 서버 + 같은 Wi-Fi의 iPhone (배포 없음)

**Mac에서 실행**
1. 이 브랜치를 Mac에 받습니다 (GitHub에서 브랜치 선택 → Code → Download ZIP 후 압축 해제, 또는 git clone).
2. Finder에서 `pharmacy/tools/start-mac.command`를 **더블클릭**합니다.
   - "확인되지 않은 개발자" 경고가 나오면 파일을 **우클릭 → 열기 → 열기**.
   - Python 설치 창이 뜨면 설치 후 다시 더블클릭합니다.
   - "python3의 수신 네트워크 연결을 허용하겠습니까?"가 나오면 **허용**.
3. 터미널 창에 iPhone용 주소(`https://192.168.x.x:8443/…`)와 CA 인증서 지문이 표시됩니다. 창을 닫거나 Ctrl+C를 누르면 서버가 종료됩니다.

처음 실행할 때 이 Mac 전용 **로컬 테스트용 CA**를 만들고, 그 CA로 Mac의 현재 내부망 IP(와 `<Mac 이름>.local`)용 서버 인증서를 발급합니다.
CA·서버 개인키는 `~/.pharmacy-scanner/cert/`(권한 600)에만 있고 웹으로 제공되지 않습니다. 웹에서는 CA **공개** 인증서(`/pharmacy-local-ca.cer`)만 받을 수 있습니다.
Mac의 IP가 바뀌면 서버 인증서만 자동으로 다시 발급되고, iPhone에 설치한 CA는 그대로 쓸 수 있습니다.
사설망·이 Mac에서 오는 요청만 받으며, 폴더 목록과 점(.)으로 시작하는 경로는 404로 막습니다.

**iPhone에 CA 인증서 설치 (처음 한 번)**
1. iPhone Safari에서 터미널에 표시된 `https://<Mac IP>:8443/pharmacy-local-ca.cer`를 엽니다.
   아직 신뢰 전이라 "이 연결은 비공개 연결이 아닙니다"가 나오면 **세부사항 보기 → 이 웹 사이트 방문 → 웹 사이트 방문**.
2. "구성 프로파일을 다운로드하려고 합니다"에서 **허용** → "프로파일이 다운로드됨" → 닫기.
3. **설정** 앱 → 맨 위 **프로파일이 다운로드됨**(또는 일반 → VPN 및 기기 관리) → "Pharmacy Scanner Local Test CA" → **설치** → 암호 입력 → **설치**.
   (선택) 같은 화면의 자세한 정보에서 SHA-256 지문이 Mac 터미널에 표시된 지문과 같은지 확인하면, 중간에서 다른 인증서로 바꿔치기되지 않았음을 확인할 수 있습니다.
4. **설정 → 일반 → 정보 → 인증서 신뢰 설정**(맨 아래) → "Pharmacy Scanner Local Test CA" **켜기** → 계속.
5. Safari의 해당 탭을 닫고 다시 `https://<Mac IP>:8443/test.html`을 엽니다. 경고 없이 열리고 "보안 연결(HTTPS): 예"가 보이면 성공입니다.
6. 앱 `https://<Mac IP>:8443/` → **바코드 스캔 시작** → 카메라 **허용** → Mac 화면에 띄운 테스트 바코드를 스캔합니다.

**테스트가 끝나면 (꼭 정리)**
- iPhone: **설정 → 일반 → VPN 및 기기 관리** → "Pharmacy Scanner Local Test CA" → **프로파일 제거** → 암호 입력.
  설치된 CA는 그 개인키를 가진 사람이 모든 사이트의 인증서를 만들 수 있게 하므로, 테스트 후에는 제거하세요.
- Mac: 서버 창을 닫고, 다시 쓰지 않을 거면 Finder → 이동 → 폴더로 이동 → `~/.pharmacy-scanner` 폴더를 삭제합니다(CA 개인키 삭제).

참고
- 공용·손님용 Wi-Fi는 기기 간 접속을 막는 경우가 많습니다. Mac과 iPhone이 같은 공유기의 같은 Wi-Fi(같은 2.4/5GHz 이름)에 있어야 합니다.
- 주소(IP·포트)가 바뀌면 브라우저 입장에서는 다른 사이트라 이전 테스트 기록이 보이지 않습니다.
- `python3 pharmacy/tools/serve_https.py`로 직접 실행해도 같습니다 (Windows는 Git for Windows의 openssl 또는 `--openssl 경로`).

### C. PC에서만 확인

`http://localhost`는 HTTPS 없이도 카메라가 허용됩니다.

```bash
cd pharmacy && python3 -m http.server 8000     # http://localhost:8000
```

### 실제 기기 인식 테스트

- `test.html` (예: `https://…/pharmacy/test.html`)에 **기기 지원 현황**과 **테스트 바코드**(EAN-13, GS1 DataMatrix, Code 128, GS1-128)가 있습니다.
  PC 모니터에 띄우고 스마트폰으로 스캔해 "원본 문자열"이 기대값과 같은지 확인하세요.
- 테스트 코드는 GS1 사내 전용 접두어(200)를 쓴 가짜 번호로, 실제 의약품과 겹치지 않습니다.
- `index.html?engine=zxing`으로 열면 기기 내장 인식기 대신 ZXing을 강제로 사용합니다(엔진 비교용).

## 2. 화면과 기능

| 화면 | 기능 |
| --- | --- |
| **홈** | 후면 카메라 스캔(조명·확대 지원 기기만 표시), 사진 찍어서 인식, 바코드 번호 수동 입력(블루투스/USB 리더기 입력 가능), 최근 입고 5건 |
| **입고 등록** | 바코드 원본 문자열·형식·인식 방법·GTIN 표시, GS1 항목 표, 약품 정보(약품명·제조사·포장단위·IT3000 박스번호), 입고 정보(공급처·입고일·수량·단위·제조번호·사용기한·메모), 실물 대조 확인란 |
| **기록 조회** | 입고 기록/약품 탭, 검색(약품명·바코드·공급처·제조번호·박스번호), 기간 필터, 기록 수정·삭제, 약품 정보 수정·삭제, CSV 내보내기, JSON 백업·복원, 전체 삭제 |

### 바코드 처리
- 인식 엔진: Android Chrome처럼 **기기 내장 BarcodeDetector**가 EAN-13·Code 128·DataMatrix를 모두 지원하면 그것을, 아니면(iPhone Safari 등) 내장된 **ZXing**(`vendor/`, Apache-2.0)을 사용합니다. 인터넷 CDN에 의존하지 않습니다.
- 오인식 방지: 1차원 바코드(EAN-13, Code 128)는 **같은 값이 연속 2회** 읽혀야 인정합니다. EAN-13/GTIN은 체크디지트를 검증합니다.
- GS1 DataMatrix / GS1-128: `(01)` GTIN, `(17)` 사용기한, `(10)` 제조번호, `(21)` 일련번호 등을 분해해 보여 줍니다. 입력란에는 원문에 `(10)`·`(17)`이 **경계가 확실하게** 들어 있을 때만 미리 채웁니다(GS 구분자로 끝나거나, 판독기가 구분자를 보존한 원문의 마지막 항목). `(10)`이 없으면 일련번호 등에서 제조번호를 만들지 않습니다. 입고 등록 화면의 **진단 정보**에서 판독기가 돌려준 원문·문자 코드·항목별 위치를 확인할 수 있습니다(인쇄된 문자열과 다를 수 있음).
- **같은 약품 판별**: EAN-13을 GTIN-14(앞에 0)로 맞춰 DataMatrix의 `(01)` GTIN과 비교하므로, 같은 GTIN이면 바코드 종류가 달라도 하나의 약품으로 묶입니다. 포장 단위가 달라 GTIN이 다르면(예: 낱개 vs 묶음 박스) 별도 약품입니다. GTIN이 없는 Code 128은 원본 문자열로 구분합니다.

### 안전 장치
- 처음 보는 바코드는 제품 정보를 추정하지 않고 빈칸(**미확인**)으로 둡니다. 목록·CSV에도 '미확인'으로 표시됩니다.
- 저장 전 "실물 포장과 대조했습니다" 확인란을 반드시 선택해야 합니다.
- 같은 약품·공급처·입고일 기록이 이미 있으면 별도 기록으로 추가할지 묻습니다. (공급처나 입고일이 다르면 항상 별도 기록)
- 수량 합계·재고는 계산하지 않습니다. 약품 목록에는 "입고 기록 N건 · 최근 입고일"만 표시합니다.
- IT3000 박스번호는 사람이 보고 적는 참고 값일 뿐, IT3000과 어떤 연동도 하지 않습니다.
- 다른 화면으로 이동하거나 앱이 백그라운드로 가면 카메라를 끕니다.

### 데이터 관리
- 저장 위치: 브라우저 localStorage (`pbs.data.v1`). 첫 저장 때 브라우저에 **영구 저장**을 요청합니다.
- **CSV**: UTF-8 BOM + CRLF로 저장해 엑셀에서 한글이 깨지지 않습니다. "엑셀용" 옵션은 GTIN·바코드를 `="0200…"` 형태로 써서 앞자리 0과 지수 표기 문제를 막습니다(다른 프로그램에서 쓸 때는 끄세요). `=`·`+`·`-`·`@`로 시작하는 값은 수식 실행 방지를 위해 앞에 `'`를 붙입니다.
- **백업/복원**: JSON 파일로 저장하고, 복원 시 현재 데이터를 백업 내용으로 **교체**합니다.
- **전체 삭제**: "삭제"를 입력해야 실행됩니다.

## 3. 보안 점검 (배포 전)

**공개되는 것** — GitHub Pages는 저장소가 공개(public)이므로 `pharmacy/` 폴더의 모든 파일(코드, 테스트 코드, 가짜 테스트 바코드, 도구 스크립트, 이 문서)이 누구에게나 공개됩니다. 비밀번호·API 키·인증서·실제 약국 데이터는 포함되어 있지 않습니다. 검색 노출은 `noindex`로 막지만, 주소를 아는 사람은 열 수 있습니다.

**공개되지 않는 것** — 입고 기록·약품 정보는 각 기기 브라우저의 localStorage에만 저장되고 서버로 전송되지 않습니다. 앱 페이지에는 CSP(`connect-src 'self'`)를 걸어 외부 서버로의 요청과 외부 스크립트 실행을 브라우저가 차단합니다. 카메라 영상도 기기 안에서만 처리합니다.

**남은 위험과 권장 사항**
- **같은 출처(origin) 공유**: `https://sunnnown.github.io` 아래의 모든 페이지(블로그 포함, 이 계정의 다른 GitHub Pages 저장소 포함)는 같은 localStorage를 공유합니다. 블로그 글 페이지는 외부 CDN(jsDelivr)에서 버전 고정·무결성 검사 없이 `marked`를 불러오므로, 그 CDN 파일이 변조되면 같은 기기에 저장된 입고 기록을 읽을 수 있습니다. **테스트에는 가짜 데이터만 쓰고**, 실제 운영 전에는 전용 도메인(별도 출처)에 배포하는 것을 권장합니다.
- localStorage는 암호화되지 않습니다. 휴대폰 잠금을 사용하고, 약국 공용 기기라면 사용 후 브라우저를 닫으세요.
- CSV·백업(JSON) 파일은 평문입니다. 다운로드 폴더나 메신저로 옮길 때 유출에 주의하고, 필요 없으면 삭제하세요.
- 앱에는 로그인이 없습니다. 휴대폰을 가진 사람은 기록을 보고 고칠 수 있습니다.
- 로컬 HTTPS 서버는 Mac에서 만든 로컬 테스트용 CA를 씁니다. CA 개인키(`~/.pharmacy-scanner/cert/ca.key`)가 유출되면 그 CA를 신뢰한 iPhone에서 다른 사이트를 가장할 수 있으므로, 테스트 후 iPhone의 프로파일을 제거하고 Mac의 `~/.pharmacy-scanner`를 삭제하세요.

## 5. 테스트

```bash
node --test pharmacy/tests/unit.test.cjs

# 브라우저 테스트 (Playwright 필요, 개발용)
python3 pharmacy/tools/serve_https.py --port 8443 &
(cd pharmacy && python3 -m http.server 8000 &)
NODE_PATH=<playwright가 설치된 node_modules> xvfb-run -a node pharmacy/tests/e2e.cjs
```

e2e는 Pixel 7 화면 크기로 수동 입력→저장→새로고침 유지→검색·수정·삭제→CSV(BOM·한글)→백업·복원,
사진 인식(4개 형식), 카메라 권한 거부, HTTP 접속 시 안내, Chromium 가상 카메라로 실시간 스캔(4개 형식),
CSP 위반 없음·외부 요청 차단, 로컬 서버의 개인키·폴더 목록 비노출을 확인합니다.
`BASE_URL=http://localhost:8001/my-blog/pharmacy/`처럼 지정하면 GitHub Pages와 같은 하위 경로에서도 확인할 수 있습니다.

## 6. 알려진 제한 · 개선 과제
